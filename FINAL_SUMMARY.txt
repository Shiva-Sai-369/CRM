🎯 WHAT HAPPENS
───────────────────────────────────────────────────────────────────────────────

SCENARIO 1: Admin Deactivates User
  1. Super admin goes to /team page
  2. Clicks [Deactivate] on a team member row
  3. Row greyed out, shows red "Deactivated" label
  4. [Deactivate] button → [Reactivate] button
  5. User's is_active set to false
  6. User banned in Supabase auth

SCENARIO 2: Deactivated User Tries to Log In
  1. User tries to log in with email/password
  2. Supabase auth rejects (user is banned)
  3. User sees "Invalid credentials" error
  4. Cannot access any part of the app

SCENARIO 3: Admin Reactivates User
  1. Super admin clicks [Reactivate] on greyed row
  2. Row returns to normal appearance
  3. User's is_active set to true
  4. User unbanned in Supabase auth

SCENARIO 4: Reactivated User Logs In
  1. User tries to log in again
  2. Supabase auth accepts (no longer banned)
  3. User gets session cookie
  4. RLS allows queries (is_active = true)
  5. User redirected to /projects
  6. Can see assigned projects, leads, tasks
  7. All their data is still there

🔍 API ENDPOINTS

POST /api/deactivate-user
  Request: { userId: "uuid" }
  Response: { success: true, message: "User X has been deactivated" }
  Errors:
    - 401: Not authenticated
    - 403: Not super_admin / Cannot deactivate super_admin / Cannot deactivate self

    - 500: Database error
